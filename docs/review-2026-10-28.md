## Public-release gates

### R1 — P1, remediated and validated for the current protected Preview

**Locations:** `receipts/extract.py:689–696,1352–1388`; `receipts/rewrite.py:310–312`; `receipts/api.py:203–221,513–515,559–560`.

In the reviewed pre-remediation build, the text extractor emits a deadline failure without usage for unfinished futures and then calls `shutdown(wait=False, cancel_futures=True)`. A request already running can finish later, but its usage is not subsequently delivered to `CheckStats` or the spend ledger. Other failures before a usable response also have no usage. `cost_usd(None)` returns zero, and Wonder costs are added only after its response returns. Settlement releases the reservation using the usage that was observed, so the reservation does not act as a conservative charge for these unknown costs.

A local mocked probe reproduced the late-response case: one fake provider response returned after 40 ms with an assigned cost of $0.025, while the operation deadline was 5 ms. The iterator returned `status: deadline` and cost $0; the worker later processed the response, but the returned accounting remained $0. Network/model calls: **0**. This demonstrates lost accounting, not an observed provider invoice or a real $0.025 charge.

**Original impact:** repeated failed or timed-out paid work could consume credit while the application ledger understated spend. Separately, each process/instance owned its own ledger; concurrent instances did not share the $1/day Preview allowance. Even complete usage can exceed an admission reservation when actual output costs more than estimated.

**Original disposition:** keep access controlled until an enforceable provider-side total-spend boundary or appropriate shared/conservative accounting is validated. The user subsequently approved remediation, a free shared database and private deployment. The validation below supersedes that initial disposition for the current protected Preview; it does not retroactively update older immutable Preview builds. No provider-side hard limit or remaining credit balance has been verified.

In the original review, Slide accounting already retained an estimate for missing usage and exposed `cost_is_estimate` on success. That alone did not coordinate separate instances or impose a provider billing ceiling.

**Remediation update:** per-attempt extraction/Wonder accounting now retains estimates for missing or malformed usage, includes retries/schema fallback, freezes deadline snapshots and prevents new attempts after cancellation/settlement. Slide terminal usage is validated once; all terminal responses expose available accounting. Durable SQLite reservations survive worker crashes and coordinate local processes; a PostgreSQL backend locks the shared daily budget row and never falls back to local storage. Vercel defaults to requiring that shared backend. API/dispatch regressions cover cache races and serialization failures before settlement. The approved free `nocap-spend` Neon database now supplies a fixed primary pooled Preview Secret, namespace `nocap`, shared-required mode and a $1/day admission allowance; automatic project connections are disabled. See [implementation and validation](spend-protection.md).

**Validation:** full Python **809 passed**; frontend **90 checks**, typecheck/lint/build passed; both dev evaluations retained the previous results with no model calls. The snapshot rebuild preserved all three examples' claim/verdict events. Actual PostgreSQL passed **8/8 checks**, including process contention, observed row locks, `55P03` rollback, duplicate settlement, unknown usage, injected UTC rollover and crash retention. Hosted checks proved missing-ledger rejection, creation of the primary budget row, and rejection of Check/Fix/Slide against the same reserved allowance across deployments B/C; cached NVIDIA remained available. Evidence: local `data/eval_runs/postgres_spend_validation.json` and `neon_guard_{missing,primary_proof,primary_B,primary_C}.json`. New model calls/spend: **0 / $0**. No paid live flow was repeated on the new build; previous live results remain historical.

## Accepted limitations and safety boundaries

- **Extraction and evidence:** the model proposes claims; code computes verdicts. A missed claim remains a missed claim. A matching filing value does not prove that an image was read correctly or that a whole draft is true. The README and slide guide disclose these limits.
- **Point in time:** the cutoff is EDGAR acceptance time, not the earliest availability through every public channel. Do not translate “Not public yet” into a claim that no one could have known the number.
- **Fix scope:** numeric substitutions preserve prose, signs, units and labels, followed by full extraction and deterministic rechecking. Ambiguous, overlapping or ineligible edits remain for review. A corrected result can retain unverifiable claims.
- **Slide boundary:** PNG/JPEG byte, dimension, pixel and animation limits are enforced before normal pixel decoding. Remote URLs and client-provided verdicts are rejected. Finite/scaled-value checks and the rule preventing axis estimates from receiving verified/wrong verdicts remain present. Images and transcripts are not locally persisted by the slide module; provider retention is not independently guaranteed.
- **Failure semantics:** application SSE `error` is terminal and has no success event afterward. Current source includes available model cost, estimation status and call count; a transport failure may still carry no accounting. Check success uses `done`, Fix uses `result`, and slide uses `done`; consumers must not mistake HTTP 200 or a partial stream for successful verification. Platform authentication or limits can respond before the SSE application.
- **Cost semantics:** cached text `done.cost_usd` is historical; a recorded replay adds $0. Current Check/Fix/Slide success and error events include an estimation flag and call count; older recordings can lack these additions. An absent error cost is displayed as unavailable, not $0. A conservative admission debit may exceed reported model cost; neither is an invoice.
- **Evidence scale:** development corpora guided implementation and share source releases with evidence. The held-out split is unrun; arbitrary writing, general slide accuracy, correction quality, time savings and customer outcomes have not been established. The user-study kit exists, but recorded real sessions remain zero.
- **Completed work stays completed:** the media production, Fireworks live benchmark, and authenticated live Check/Fix/Slide Preview are real completed work. Baseten/Modal validation, Ask mode and MCP team authorization are optional follow-up scope, not prerequisites for the already demonstrated core pipeline.
